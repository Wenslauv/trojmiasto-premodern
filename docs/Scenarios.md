# Scenarios

## Data layout

- `data/events/` — one JSON file per event, the single source of truth
- `data/incoming/` — drafts of new events before import
- `data/templates/` — starter JSON templates for new events
- `public/data/` — generated by `npm run generate-data` (`events.json`, `cache/*`); not committed, rebuilt before `dev`/`build` and in CI

Event files may omit `name` (defaults to `<place> <type>`) and `mode` (defaults to `roundByRound`).

## 1. Add New Round-by-Round Event

1. Create a draft from the template:

```bash
npm run new-event-file
```

This creates `data/incoming/incoming_DD.MM.YYYY.json`. Alternatively, copy the template manually:

```bash
cp data/templates/new-event.template.json data/incoming/incoming_DD.MM.YYYY.json
```

2. Fill event data in the draft.

3. Validate:

```bash
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY.json --dry-run
```

4. Add the event (creates `data/events/<place>_DD.MM.YYYY.json`):

```bash
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY.json
```

5. Validate + build (the build regenerates site data):

```bash
npm run check-data
npm run build
```

6. Commit the new file from `data/events/`.

## 2. Add New Event and Remove Draft File

```bash
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY.json --delete-source
npm run check-data
npm run build
```

## 3. Add Standings-Only Event

Create a draft from the standings template:

```bash
npm run new-standings-file
```

1. Fill the draft with:
- `mode: "standingsOnly"`
- `standings[].match`
- `standings[].game`

2. Run:

```bash
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY-standings.json --dry-run
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY-standings.json
npm run check-data
npm run build
```

## 4. Add Event With Dropped Players

1. Use `mode: "roundByRound"` (or omit mode).

2. Omit missing rounds for dropped players.

3. Run:

```bash
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY.json --dry-run
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY.json
npm run check-data
npm run build
```

## 5. Reuse Existing Players Quickly

1. In `standings[]`, use one of:
- `playerRef: "pNN"`
- `playerRef: "Full Name"`
- `playerRef: "alias"`

2. For a new player, provide `playerName`; the ID is auto-generated.

3. Validate and apply:

```bash
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY.json --dry-run
npm run add-event -- --file data/incoming/incoming_DD.MM.YYYY.json
```

## 6. Fix Existing Event

1. Edit the event file directly in `data/events/`.

2. Validate the edit:

```bash
npm run update-event -- --file data/events/<event-file>.json --dry-run
```

3. Apply: re-normalizes the file in place (resolves players, recalculates standings totals from rounds):

```bash
npm run update-event -- --file data/events/<event-file>.json
```

4. Validate, build and commit the event file:

```bash
npm run check-data
npm run build
```

## 7. Update Matchup Deck Merge Rules

1. Edit `config/matchup-deck-rules.json`.

2. Rebuild the matrix only:

```bash
npm run generate-matrix
```

3. Full verification:

```bash
npm run build
```

## 8. Reset and Rebuild Matchup Matrix

```bash
npm run reset-matrix
npm run build
```

## 9. Local Development Run

```bash
npm install
npm run check-data
npm run dev
```

`npm run dev` regenerates `public/data/` before starting.

## 10. Pre-Deploy Checklist

```bash
npm run check-data
npm test
npm run build
```

Commit only source files: event files in `data/events/` (and `config/` or `data/templates/` when changed). Generated `public/data/` is rebuilt in CI.
